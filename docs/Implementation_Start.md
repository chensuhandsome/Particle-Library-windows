# 首批实现任务与就绪边界

版本：1.0　日期：2026-10-13

第一条可交付流程是：离线打开应用 → 按 PDG identifier 查到条目 → 查看全部衰变目录 → 打开模式 → 查看原始参与项与相关量 → 打开完整测量、脚注和文献 → 返回原位置。它验证数据连接与实际页面，不依赖先解决全部复杂衰变语法。

产品范围和公共规则以[总体设计](PDG_App_Design.md)为准，衰变语义以[衰变专篇](Decay_Structure_Design.md)为准，字段含义查[数据清单](PDGall_Data_Atlas.md)。本文规定开工顺序，不降低首版最终功能要求。

## 1. 当前能够开工的范围

| 工作 | 当前就绪情况 | 开工边界 |
|---|---|---|
| Flutter 工程、主题、基础导航 | 可以开始环境与最小工程验证 | iPhone、macOS arm64；不做 Intel Mac |
| 原库只读访问、原始行模型 | 表结构、字段与关联已有依据 | 字段无损映射，不猜物理含义 |
| 条目、目录、参与项、相关量读取 | 关联规则明确 | 返回全部行和真实父子边，不生成级联关系 |
| 原始测量、全部列、脚注和引用 | 关联规则明确 | 不过滤未用于平均/拟合的值，不丢文本列 |
| 原文详情、深层树、返回恢复 | 交互方向明确 | 先完成真实数据流程，再逐步扩充页面 |
| 通用衰变语法与精确末态查询 | 尚不能整包交付实现 | 先形成逐规则输入、输出和反例，再开放相应类别 |
| 跨粒子数值条件 | 尚缺实际定义绑定集合 | 不可只按 M/G/T 类型自动合并物理定义 |
| 全套名称规范化和中文别名 | 尚缺完整种子与预期候选 | 首步只按完整 PDG identifier 精确查询 |
| 真机性能与发布 | 尚无实现证据 | 工具链、签名、设备、产物逐项验证 |

“可以开始”不等于已经实现、编译或验收。当前已有的 SQL、字段统计和原始例项是输入，不能直接替代应用测试结果。

## 2. 固定决定与未定事项

固定：Flutter/Dart、本地 SQLite、原始库只读、用户数据与派生索引分离；iPhone 与 Apple Silicon Mac 首发；Intel Mac 暂不支持。首批任务不引入 Rust、Node/Python 运行时服务、网络数据补全或后台更新服务。现有 Python 核查程序仅用于开发数据核查，不随应用运行。

工具链和依赖版本必须以实际可构建结果记录并锁定，不能在本文预填未验证版本。首批页面使用 Flutter 自带的导航和通知机制即可；SQLite 与应用目录访问采用通过实际 Apple 构建的最小依赖。全局状态库、路由库、Drift 和全文检索方案不是首批任务前提，增加它们之前须记录具体需要，不能因总体设计列出备选就全部安装。

代码许可证、正式品牌、商店信息不由实现者自行认定。可先开发本地工程；这些决定到发布准备时必须明确。最低系统版本由实际工具链验证后记录，不以开发主机的当前系统版本直接代替。

## 3. 首批读取接口

先实现以下窄接口，后续搜索和数值查询在此基础上扩展。所有接口异步执行，数据库连接在后台独占持有；页面不直接访问 SQLite。

| 接口 | 输入 | 输出及固定行为 |
|---|---|---|
| `openSnapshot` | 应用容器内数据库文件 | 哈希、edition、schema、release；不兼容或损坏为明确错误 |
| `findEntryExact` | `snapshotHash`、完整 `pdgid` | 0 或 1 个原始条目；0 是未收录，多行是数据错误 |
| `listChildren` | `snapshotHash`、`entryId` | `parent_id=entryId` 的所有子项，按 sort、id；不按 BF 类型裁剪路径 |
| `getDecaySource` | `snapshotHash`、BF 条目键 | 模式原始行、全部 token、名称项、直接身份及映射边；不自动选择候选 |
| `listRelatedQuantities` | `snapshotHash`、模式键 | 全部映射边及目标原始条目，按映射 sort、id；不把目标改名为 BF |
| `listSummaries` | `snapshotHash`、系列键、显式 edition | 本系列本版全部行，按 sort、id；不隐式调用 best summary |
| `listMeasurements` | `snapshotHash`、系列键、可选 cursor | 一页 measurement 及每条全部 value、脚注和引用；完整组不可跨页拆分 |
| `getReference` | `snapshotHash`、引用行键 | 原始书目字段；缺题名或无测量链接仍可返回 |

返回壳固定包含 `snapshotHash`、调用方提供的 `requestId`、`status`、`data` 和 `error`。`status` 只取 success / notFound / error：存在的空子列表是 success，找不到请求的父对象才是 notFound。error 带稳定错误码：unsupportedSchema、invalidInput、snapshotMismatch、corruptDatabase、queryFailed；不得把查询异常吞成空列表。未知名称项身份在 data 内保留全部候选，不能误报数据库错误。

原始模型按字段清单逐列定义 nullable 类型；NULL、空串和零严格分开。每个返回对象保留源表名、源行键和快照哈希。第一批不把缺数值的文本强转成浮点值，不转换单位，也不推导寿命或宽度。

测量分页每页 50 条，排序为 measurement.sort、measurement.id。cursor 至少包含快照、系列键及上一条的 sort、id；下一页使用严格大于的字典序条件。cursor 与请求快照/系列不符时返回 invalidInput，不悄悄切换系列。子 value/脚注单独按本页 measurement ID 批量读，避免多重连接扩张；反复翻页的完整集合须与原库集合相同。

上述接口是首批合同；总体设计中的 QuerySpec、定义绑定与三态结构查询接口另行实现。第一条流程不需要伪造尚未成立的结构匹配结果。

## 4. 有依赖顺序的任务

### T00：最小工程与平台记录

输入：总体设计 §2、§9、§12，以及本节的固定范围。

产出：最小 Flutter 工程、提交的 lockfile、工具链与目标系统版本记录、中文/英文和浅/深主题入口。源目录按 `lib/app`、`lib/domain`、`lib/data`、`lib/features` 分责；平台文件由所冻结 Flutter 工具生成，不能手写臆测的签名配置。

完成条件：macOS arm64 最小应用能实际构建和启动；iPhone 构建/安装情况另行记录。缺 Xcode、签名或设备时写明具体缺项，不能以桌面运行代替 iPhone 验收；仍可推进不依赖设备的数据工作。不要申请证书、注册商店或增加 Intel 构建任务来扩大本项范围。

### T01：源快照与无损字段读取

依赖：T00 的 Dart 与 SQLite 可运行环境，不依赖商店账户。

输入：外部提供的 `pdgall-2026.0.sqlite`、字段清单和已有核查程序。开发路径通过 `PDGAPP_SOURCE_DB` 指定，不硬编码某台机器的绝对路径。预期基线 SHA-256 为 `c82dab0c0a7c5264f23508066cabb8df9eacc1dbfc83c8d20fade6053394ba8a`；若不同，先辨认快照，不能沿用旧计数或自动下载替换。

产出：`lib/data/snapshot`、原始行模型、应用容器内只读连接、明确失败状态。先输出元信息与表行数，后续按需读取；不要把全部测量载入 UI 内存。

完成条件：15 张表、128 字段均有明确去向；记录读前读后哈希，原库不变。NULL、空串、文本值及全部误差字段精确保留；未知字段/编码不能无声丢弃。数据库没有写权限时仍能查询，失败时页面不显示“无数据”。

### T02：固定条目到测量的读取流程

依赖：T01。

输入：第 3 节接口、衰变专篇 §9 的 SQL、D⁰ 条目 `S032` 和衰变 `S032.1`。

产出：`lib/data/repositories` 中的条目、衰变、相关量、汇总、测量和文献读取；`test/data` 中与原始 SQL 对照的集合检查。预期数据从源表提取并保存来源键，不从待测 repository 反向生成。

完成条件：D⁰ 目录及模式能读到所有源参与项和相关量；每个相关量可到达其全部测量和全部值列。分页合并后与原始 measurement ID 集合精确相同，脚注附件集合也精确相同；BF 无直接 measurement 不能显示成没有相关实验。无相关量和无汇总分别是正常状态。

### T03：第一条真实页面流程

依赖：T02。读取工作与页面实现不可仅通过手工抄来的静态 JSON 接通。

产出：精确标识搜索、条目页、衰变目录、模式原文详情、相关量页、测量页和文献页。窄窗口单列、宽窗口列表与详情并排；这些页面与总体设计共用颜色和字体规则。

完成条件：完成本文开头的离线流程；关闭网络仍能读本地内容。返回保留选中项、展开状态和滚动位置。加载、空列表、未收录与查询失败分别显示。原文显示与复制一致；模式目录展开不自动解释为粒子级联。此时可显示原始量字段，但未经完整格式化核查的值必须标为原始记录，不能包装成完整推荐值。

### T04：格式化与原始例项覆盖

依赖：T02，可与 T03 的布局工作分别推进，但整合后须检查页面和复制。

产出：统一显示对象，以及以下可自动核对的原始例项。显示十次幂、百分比、上下限、误差与单位遵循总体设计 §5；原字段不作单位换算。

| 例项 | 必须保留 | 禁止结果 |
|---|---|---|
| `S009.1` | 两个光子的 multiplier | 去重为一个光子 |
| `S035.218` 与 `S035.27` | 真实目录关系和排除条件 | 目录边画为级联边 |
| `S035.286` | 两阶段的完整原表达 | 跨阶段合并旁观粒子数量 |
| `S035.319` | 无 outgoing 时仍有原描述 | 显示空末态 |
| `S043.1` 及相关量 | 保留每个比值的原定义 | 相关比值充当电子道 BF |
| `S016.22` 与 `S016T22` | 各自原值及单位/尺度缺失状态 | 从不同记录拼成一个数值 |
| `pdgitem_id=1593` | 两条不同 listing 身份 | 自动选首条 |

完成条件：原始字段及源关系精确相同；格式化后的完整显示、复制和读屏文本一致。真实例项不足以覆盖的 NULL/非空外键等状态用标明 synthetic 的样本补充，不称其来自 PDG。文本拼接一致只能验收表示恢复，不能验收物理语义。

### T05：先冻结结构规则，再实现结构查询

依赖：T02、T04 的原始数据例项。

产出：每条规则的输入原文/token、预期表达式、未解析片段、允许查询作用域、真/假/未知的预期模式集合和反例。至少先覆盖单阶段唯一身份、重复数和含明确包容项三类；多箭头、耦合电荷及动力学限定分别建规则。规则输入和预期输出核定后，才实现相应解析器分支。

完成条件：全部原文字符被保留或定位为未解析片段；确定命中、排除和待判构成查询范围的完整分割。两个不同阶段的产物不能共同满足同阶段条件。不能先写宽泛正则，再以其输出作为预期答案。复杂语法尚未核定时，继续提供原文读取并列出待判，不阻塞已核定类别，也不谎报精确查询完成。

T00–T04 构成首批实现包。T05 中的物理规则冻结是明确的前置工作，不能把整项交给实现者自由猜测；跨粒子定义绑定、中文别名、全文检索、收藏迁移和最终发布随后分别拆包。

## 5. 全部首版交给实现者之前仍须补齐

| 缺口 | 应交付的具体材料 | 未完成时的处理 |
|---|---|---|
| 通用领域类型 | Dart 字段、nullable、错误和序列化契约 | 仅实现本文的窄读取接口，不临时创造全局协议 |
| 结构语法 | 每类规则、完整 AST 例项、作用域、反例及来源 | 对未核定语法保持原文和待判 |
| 定义/变体绑定 | 真实条目与量定义、电荷适用关系、单位映射 | 不开放相应跨粒子数值条件 |
| 自动预期集合 | 名称、普通条件、衰变查询的具名输入与结果文件 | 不能用“计划 100/40/30 个”声称已有测试 |
| 用户数据库 | 收藏/查询的实际表结构、迁移与失败恢复 | 原始查询先可用，收藏另包实现 |
| 剩余页面状态 | 每页状态、事件、返回与复制预期 | 不要求实现者从静态预览猜交互 |

这些缺口不需要在开工前一次解决，但每项相关开发开始前必须有确定输入。完成第一条真实流程之后，再扩大搜索、性质绑定和结构语法范围，避免一次生成全应用后才发现数据模型不成立。
